## 三项可复查发现

### F1 / P1：失败阶段的结果仍可发布

`src/quanthus/hf_dwd_research.py:503` 的 `build_package` 检查结果与输入摘要，随后只把
`resources.json` 和 `attempts.json` 装入包，没有要求 fetch/screen 最终成功。
screen 子进程先写 result/run，Guardian 后写终态；进程退出前超限或被终止时，可以留下
合法结果文件及失败阶段回执。

合成反例保留真实 A2 输入、fetch、result、run 字节，仅将 screen 操作回执设为
`exit_code=-9, failure=rss_exceeded`，再调用未修改的 publish。离线 HF 替身观察到一次
`create_commit`，发布没有拒绝。原始 A2 及远程 HF 均未修改。

修复责任：由 Guardian 写入绑定 identity、attempt 和 result digest 的终态成功证据；
封包和发布的首次/重试分支均校验它。失败、缺失、未完成、旧 attempt、混用 identity
必须在创建远程 commit 前拒绝。资源超限之后文件存在不能充当阶段成功。

### F2 / P2：候选样本天数误用了对照组

`src/quanthus/hf_dwd_research_sql.py` 的 `sufficient` 使用
`x['control']['decision_days']`。候选的时间覆盖门槛应使用候选本身。
反例冻结每年最少 3 天：候选各 1 天，对照为 219/5 天，当前实现却给
`sample_sufficient=true, decision_branch=small`；应为 `insufficient`。

将门槛改为候选天数，并加入正好达标/差一天、对照充分而候选不足的反例。
本次 A2 的候选实际有 207/242 天，所以这项修复不会改变其已验证分支。

### F3 / P2：封包中断后普通重试无法恢复

`build_package` 直接创建最终 `package/`，然后逐个写文件。若中途退出留下 request
但尚无 manifest，下一次看到目录已存在就当完整包校验。连续两次均报
`GuardError: package manifest cardinality`。

采用 staging → 完整校验 → 原子命名的最小封包方案；既有半包移入可追溯隔离目录后
从成功计算输出恢复。完整包仍保持逐字节不可变，重试只封包/传输。需要明确区分可恢复半包
与已经宣称完整但校验失败的包，后者保留失败证据并停止。

反例入口：`scripts/research_r1_v2_fault_probes.py`；纯合成门槛和离线发布替身，网络写入为 0。
