## 1. 目标与现状归因

本次是阅读产品整改，不重做数仓、公式、Facts 或策略。既有确定性构建、权威来源与只读
权限保留。原 P3-DICT-001 验收记录不改写；它证明旧范围，不替代本次产品验收。

现有三个问题：内部覆盖检查作为“已知缺口”出现在业务首页；524 个 DWD 字段使用
占位式英文说明；归属/概念关系被标成上下游，且没有完整加工视图。

## 2. 信息分层（A）

业务首页取消“已知缺口”统计和展开面板。构建器的 gaps、验证与维护报告继续存在，
不删除检测、不把未实现包装为可用。具体条目仍显示必要的使用限制及“仅概念 / 暂无计算
规格”等状态。业务限制、概念登记状态和开发待办不是同一种信息。

业务 summary API 不再返回 `gaps` 和 `summary.gap_count`，内部 `diagnostics()` 与构建
清单继续保留它们；其他现有字段保持。该有意收缩的业务响应与 Web 成对发布，不增加新的
维护后台、数据库或治理服务。

## 3. 中文业务卡片（B）

所有可发现条目均有中文主名称及实质性说明，英文 canonical ID 保留为次要信息及复制
入口。DWD 共享字段可复用经过审阅的词典，必须带所属表上下文；同名不同义字段采用
表级覆盖（尤其证券价格与指数点位、成交量/成交额、单位及比例）。

卡片默认展示：含义、粒度/窗口、单位或取值、时间口径、使用注意。指标明确实际输入、
T 是否包含、历史要求、缺失语义；不得把旧 SMA/RSI 改写成另一种公式。技术详情默认折叠，
包含原始契约、版本、类型、路径及摘要。未知单位不猜，说明依赖的单位字段或规格。

版本化业务说明绑定既有条目与出处，不能创造条目、公式、语义等价、验收状态或交易权限。
源契约或说明变更必须刷新目录清单；新增条目缺少中文说明时检查失败，而不是退回英文
模板。对 source-evidence 等技术数据集也说明用途，不伪称可供策略直接计算的行情。

## 4. 真实血缘与视图（C）

新增有来源约束的加工图，保留旧 relations API 兼容。全局图按业务层折叠；字段/指标
焦点图采用左上游、中间焦点、右下游的双向鱼骨式布局，支持逐层展开与点击重新聚焦。
箭头统一为输入 -> 输出，显示加工说明、字段/数据集粒度及证据来源。

关系分开：

- 加工依赖进入主图；支持共享输入、汇合和多消费者，不强制成树。
- contains / field_of 属于结构归属，不当作加工边；展示在所属对象或技术关系区。
- related_not_equivalent 等属于概念关联，不进入数据加工链。

只依据明确的来源契约、转换实现或已登记 Feature/Label 依赖建边。不凭相似名称、代码
全文搜索或公式字符串猜测关系。必要的研究投影可以作为明确标注的图内节点，不冒充 ODS
或新增计算产品。字段级、数据集级与概念规格级证据必须区分。概念节点不代表具体运行
实例；消费依赖不代表某个历史 Job 实际使用，实际使用仍由独立审计日志证明。

全局图和焦点图必须展示覆盖范围，节点/深度截断不能悄悄省略。不登记下游表示“目录尚未
登记”，不等于没有消费者。图本身只读，无市场值查询和运行发起权限。优先采用现有 Web
栈和 SVG，不增加搜索引擎、图数据库或图形依赖库。

### 4.1 字段焦点完整性修订

用户以 `dwd_adjustment_factor.effective_from` 发现：原实现虽然有表级 ODS→DWD 血缘，
但绝大多数 DWD 字段没有字段级加工边，焦点图会只显示字段自身。该行为属于产品语义缺陷；
免责声明不能把孤立节点变成有效血缘。

每个 DWD 字段焦点现在必须明确返回一种证明级别：

- `field_proven`：存在直接以该字段为输入或输出的、证据绑定的加工边；主图可展示这些实线关系；
- `table_context_only`：没有精确字段映射，但所属 DWD 表已有声明的加工关系；主图保持字段孤立，
  另开“所属表加工上下文”视图，明确该上下文不能推断字段参与了表的每个来源或消费者；
- `field_unregistered`：连所属表加工上下文也不存在，必须显式报未登记，不能只显示自身而无说明。

`field_of` / `contains` 仍不能转成加工边，也不能用 ODS→DWD 表级关系自动生成虚假的
ODS 字段→DWD 字段映射。全局概览必须公布 DWD 字段三类覆盖数量，使字段级能力边界可审计。

`dwd_adjustment_factor.effective_from` 是强制反例：源码证明
`adjustment_factors_pit.effective_date` 经日期解析和 `_effective_start()` 形成该字段；
`close_adjustment_factor_intervals()` 又使用它关闭 `effective_to`；P4 Event Library 的
`factor_boundary` 读取它形成 `factor_effective_from` 及当日复权边界标记。该链必须作为
`field_proven` 展示。

## 5. 工单顺序及验收（D）

A 冻结产品边界并移出首页治理面板 -> B 补齐所有条目中文卡片 -> C 登记并展示加工图 ->
D 综合审计、工程验证、Git 发布与生产烟测。父工单在子项证据落盘之后关闭。

验收包括：全目录中文覆盖且非模板占位；SMA/RSI/成交额/历史时间等语义反例；图无归属
伪边、概念等价伪边、倒向依赖或无证据关系；权限和查询上限；桌面/窄屏实际渲染及交互；
确定性重建、源摘要、受影响测试和 make check。没有执行的检查如实记录，不用源码正则
测试冒充浏览器验收。不得修改 DWD 数据、Facts 数值、专家映射或执行权限。

## 6. 实现落点

`src/quanthus/data_catalog.py` 保持权威投影；新增业务说明及加工图模块/配置；Platform
GET 查询扩展：summary 提供分层概览，既有 relations 路由增加 `lineage`，并接受
`depth=1..5`、`limit=10..100`（默认 2/60）；可在已登记图内投影或加工节点上重新聚焦。
默认搜索最多显示 100 项，超出时明确要求缩小范围；此版不宣称有分页。
`web/app/catalog-browser.tsx` 及独立图组件；目录 unit/platform/contract
测试与 Web 渲染/交互测试。验收记录落在 `docs/acceptance/`，工单入口在
`docs/work-items/catalog-productization.md`。

## 7. 来源与证据维护

`config/catalog-business-metadata.v1.json` 只负责经过核对的中文阅读表达；
`config/catalog-lineage.v1.json` 登记加工依赖和精确实现文件摘要/定位。构建图同时读取
DWD 模型中的 `modeled` 来源映射，覆盖 static/release/weekly/container/hotfix 声明。
图中新增的逻辑工件节点不是 Catalog 新数据集，也不是已验证物理包成员。字段映射仅覆盖
经核对的行情与研究链，不声称所有 DWD 字段都有端到端血缘。

仓库测试校验每项代码摘要及定义位置，拒绝悬空端点、循环、无证据边和归属伪加工边。
运行镜像只携带目录投影所需模块/配置，不为目录装入整个分析运行环境。升级实现版本后
必须先复核依赖与摘要，再更新快照清单。静态图与真实消费审计是不同产品证据。
