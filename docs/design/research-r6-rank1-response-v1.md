## 目标与选择

本批为 #608 的研究投入分配取得一个新决定：已有全市场单选入口是否承接 R5 的
总体两开盘价格信息，从而值得继续查证具名经济消费者，还是停放该消费路线。
R5 的总体均值与 R4 的资金路径之间，尚缺原名义 rank1 的统一价格响应。

按取得答案的完整成本比较三项：

1. 先复用旧费用/占用报告。候选/对照总费用 5951.40/5988.47 元，费用差 37.07 元，
   原净利润差 2634.07 元；平均投入比 11.614494%/12.234322%，平均持有均为两会话。
   这些结果足够维持原资金用途 park，新增费用研究暂缓。费用是账面科目；成交价中
   另含既定滑点，费用加回仅描述原路径。
2. 选择原名义 rank1 的价格承接诊断。冻结已有 898 行选择，无需改选择器或资金引擎。
   这是唯一正式比较；旧 R5 汇总重建只作输入/时钟控制验证。
3. 五单元组合接线后置。现有接口使用另一套策略；还需多账本、行业和公司行动用途
   资格。先有具体需求和可解释的新信息，再评估这些成本。

## 冻结输入和选择顺序

复用 R5 请求中固定的 56 个成员、187921175 字节、25 包 Linux Python3.10.12
环境和原始未复权价格口径。请求文件、closure、环境、源码、旧 R4/R5 结果均有
完整摘要。源缓存或 HF 固定 revision 二选一；每次逐文件校验，独立构建物理复制。

原 R4 的 898 行名义选择包含 449 个 T 日的两臂。排序是每 T 日/每臂全市场
`round(return_vol20,12)` 升序，再按 opaque `listing_id` 升序，仅取第一只。
排序只使用 T 收盘已定义的原筛选；先选中，再判断标签资格，失败不补 rank2。
重新构建的 T 日名单必须逐键、排序值一致，否则停止为实现/输入不一致。

T 为 2020-03-02 至 2021-12-30。市场行读取止于 2021-12-31；12/30 两臂保留
在分母并标记第二会话右删失。主标签使用至 12/29 的 T+1 开盘到 T+2 开盘原始
价格响应，与 R5 完全相同的第一开盘守卫及共同标签资格。缺少日历会话时不跳到
下一根观测 K。2022+ 保护窗保持关闭，P10 数据边界保持。

完整名义账保留 date、arm、listing、venue、排序值、decision_hold、标签原因、
两个计划开盘时钟、有效响应和原资金闭合交易入场关联。decision_hold 不用于事后挑选主样本。
原资金闭合交易按 listing/首开盘日期关联，仅作身份描述；未闭合尾仓不在该标记内。
主样本是每日名义选择，
包含资金占用期间的选择。

## 主指标、桥接和分支

仅两臂均有有效标签的 T 日参与配对，每日候选 rank1 响应减对照 rank1 响应，
再等权日期。分年按 T 年。每年需至少 200 配对日，列出全部原因/年/臂分母、
有效未配对行、不同股票数和重复集中度。集中度为此消费机制的描述，不据结果
更换排序、扩充篮子或新增优胜门槛。

主区间固定分年分层、连续 20 个合格配对观察的循环块、2000 次、seed=20261113、
nearest-rank 95%；两臂始终按同一日期成对抽样。缺失造成的配对日期间隔另列，
不把这个沿用算法描述成连续 20 个权威交易日。浓度报告还包括同股最长连续选择。
至少 5bp 的平均增量、区间下界>0、分年均>0时保留此选择器价格证据，下一笔仅查
具名经济消费差集；区间上界<5bp 时停放该承接路线；样本不足或其余情况为不确定
停放。5bp 是沿用的信息价值门槛。R4 的固定持仓资金用途在所有分支继续 park。

R5 是每日期两个 venue 等权总体，原 rank1 是全市场单选，两者权重不同。在相同
配对日期，另输出 R5 总体、按两臂各自所选 venue 的总体均值、rank1 的三层桥接：
日期选择差、venue 构成差、venue 内选中股票与总体的描述差，保持加和恒等式。
设原 R5 全窗为 P0，共同日期总体为 P，所选 venue 总体为 V，rank1 为 R，
若桥接存在缺失，R 使用 R_bridge 表示可桥接子集均值；主均值仍保留完整主配对样本。
则日期差=P−P0，venue 差=V−P，venue 内选择残差=R_bridge−V，三者相加=R_bridge−P0。
这组桥接解释口径，不作为第二个假说检验或排序因果归因。缺失任何所需总体单元
要完整登记；主配对与可桥接子集分别报告。

## 三阶段执行与失败路径

1. 选择与冻结：核对消费者、旧证据和成本；独立审阅合同及代码、合成负例通过；
   固定 GitHub 提交后，Nexus 在隔离目录取得代码。未经预审不运行新市场响应。
2. 一次正式、一次独立：正式 SQL 与独立 pandas 分别重建输入和时钟，验证全部
   名义选择、逐行标签、分母、主统计、桥接与原 R5 控制汇总；自审后独立结果验收。
3. 交付：按预设分支落实投入决定；源码通过完整本地检查和普通 PR 合并；结果以
   request/task/attempt 命名进入私有 HF，固定提交逐文件回读；仅长期证据留 CN02。
   回写结论、蓝图、父工单和里程碑，核对残留进程、临时分支/目录和留存条件。

单次正式/独立计算各 <=180 秒、CPU<=240 秒、RSS<=6GiB、scratch<=2GiB；准备
<=300秒且实际下载<=512MiB，回传单次<=180秒且<=4MiB，至多三次传输尝试。
完整工作预算规划两小时主动工作；完整回归等待单独实测。启动前成本未知而非零，
R1/R2/R4/R5 的曝光、失败和成本继续累计。Worker 维持备用。

身份、分区、重复键或名单不一致：保存失败并停本阶段；共享数据差集交 P10。
预算触顶：停止进程组并保留尝试；新正式计算须重新评估边际价值，不能直接重试。
第三次同点修复、扩建选择器/资金/行动用途或新增样本，触发 ROI 重审。传输失败仅
重传相同字节，保留原计算时钟与结果；三次后交付准确待回传状态及恢复条件。
工程交付、研究有效性、用途价值与消费者准入各自记账。
