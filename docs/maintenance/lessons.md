# 工程教训触发导航

本页是正常开发任务的检查入口，原设计、测试与工单继续持有领域权威。规则实现见 `config/maintenance-checks.v1.json`。

## 本任务开始与提交前

1. 记录任务的精确base；运行 `python scripts/maintenance_checks.py --base <base>` 查看本次触发项。
2. 使用项目规定Python（3.10+）加 `--run` 执行现有检查；检查失败由变更作者和当前PR审阅者接手。
3. 在原任务验证记录中写适用规则、版本/提交、检查动作和实际结果。范围由审阅者判断，机械路径匹配用于提醒。
4. 交接前查看所关联Issue的最新评论；用户结果和代码窗口分别跟进。

## Q-RECOVERY-COMPAT

- 状态：active，复用现有规则/检查；后续采用和收益按自然任务观察。
- 原权威：docs/operations/ods-dwd-incident-log.md。
- 何时适用：本次修改仍需复用同市场日封存lane的恢复、编排或合同兼容路径；按当前产品路径判断。
- 具体动作：运行原编排、catalog与schedule检查；审阅恢复补丁是否可与既有manifest组装，是否复用过期deadline。
- 失败接手：当前恢复变更作者及P10审阅者；数据修复仍归P10。
- 观察结果：局部恢复引发的二次返工、恢复到可用包的时间、完整性；记录当前产品/合同。
- 合法反例：正式批准的合同升级走原升级/重建流程；本条不要求永远保留旧合同摘要。
- 下次复查：下一次满足触发条件的真实变更/任务；暂无机会记等待。

## 规则维护

候选教训写事实、原因判断、原事故与日期、触发范围、下次检查及原权威落点。同事故重投不增加次数；普通重复参考三个独立日期升格，严重确认问题及时固化。激活时优先补原测试/运行手册，导航只保留短说明。

后续记录适用机会、是否执行、同类返工/逃逸、误阻、实际运行/人工成本；复发分漏执行、覆盖不足、执行错误或环境变化。根据证据保留、收窄、修订或退役；无触发不自动删除严重安全/完整性约束。

本页服务工程复盘；策略/模型学习资产仍沿原research/consumer权威，数据修复归P10。
