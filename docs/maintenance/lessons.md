# 工程教训触发导航

本页是正常开发任务的检查入口，原设计、测试与工单继续持有领域权威。规则实现见 `config/maintenance-checks.v1.json`。

## 本任务开始与提交前

1. 按任务目标、模块和运行场景选择少量本仓相关条目，在恢复、派工或验收等决策之前读取原权威并采用；无代码变更的任务也按场景判断。
2. 代码任务记录精确 base；运行 `python scripts/maintenance_checks.py --base <base>` 查看路径触发项，再用本仓规定 Python 加 `--run` 执行现有检查。检查失败由作者和当前 PR 审阅者接手，项目完整检查继续按原要求执行。
3. 在原任务记录适用规则/方法及版本、具体动作、实际结果和额外成本。审阅者判断语义适用性，路径匹配负责提醒。
4. 交接前查看所关联 Issue 的最新评论，接续已有成果；代码窗口与用户结果分别跟进。

## 值得保留的工作经历

明显返工、有价值的成功探索或重点方法的实际使用，在原任务留一条简短收尾：目标与条件 → 关键尝试和结果 → 有效路径改变了什么及原因证据 → 原实现/测试/Skill/手册的具体改进 → 适用条件与合法反例 → 下一次使用机会和接手人。已有记录足够时直接引用。

夜审从选中的案例串联失败与成功路径，区分原因、假设和待补证；最终 diff 缺少过程时，由控制 Agent 按原任务引用定点读取真实节点记录，或将补证交给原作者。正式只读审阅器使用预取的 PR/审阅/CI/Issue 输入和固定源码；来源不足时写出具体缺口。完整会话和日志保留在原节点/私有 HF，GitHub 只留脱敏结论与必要引用。

确定性缺陷修原实现和测试；反复遗漏补原检查；语境判断修原 Skill/任务入口；成功方法在下一相似自然任务有限试用。验证覆盖原失败与合法相邻场景。新探索沿原项目授权，先说明预期改善、比较条件、成本和停止条件。

## Q-RECOVERY-COMPAT

- 状态：active，复用现有规则/检查；后续采用和收益按自然任务观察。
- 原权威：docs/operations/ods-dwd-incident-log.md。
- 何时适用：本次修改仍需复用同市场日封存lane的恢复、编排或合同兼容路径；按当前产品路径判断。
- 具体动作：运行原编排、catalog与schedule检查；审阅恢复补丁是否可与既有manifest组装，是否复用过期deadline。
- 失败接手：当前恢复变更作者及P10审阅者；数据修复仍归P10。
- 观察结果：局部恢复引发的二次返工、恢复到可用包的时间、完整性；记录当前产品/合同。
- 合法反例：正式批准的合同升级走原升级/重建流程；本条不要求永远保留旧合同摘要。
- 下次复查：下一次满足触发条件的真实变更/任务；暂无机会记等待。

## 规则维护

先查同义原规则和既有修复，优先改最早造成问题的入口。按严重度、证据、适用机会和成本决定修复/试用/固化；重复日期仅作证据，不设固定日期门槛。激活经验须指向普通任务的执行点，本页保留短导航；暂无机会的候选保存原引用、下一触发条件和接手人。

分别记录适用机会、实际采用、直接结果、误阻与额外运行/人工成本；同一任务重试算一次机会，缺数据记未知。复发区分漏执行、覆盖不足、执行错误或环境变化，据此保留、修订、收窄、替换或退出。低频高风险保护按风险保留。

每周在既有每日任务内做一次仓内趋势复核，查看跨任务返工、不断放宽的条件、漏用/误阻、成功方法复用和维护成本；沿原报告保存本仓上次完成时间与下一动作。效果随自然任务观察，既有业务成果按原项目归属。

## 仓内优先与按需借鉴

日常优先本仓问题和已采用方法的反馈；取消每日/每周跨仓经验扫描与推送。潜在共性只保留来源引用，休眠保存。目标仓有具体问题或近期同类任务时，再比较减少返工的预期收益与理解、适配、验证、打断、误用及维护成本；已有更简单等效方法就复用本地方法。

实际借鉴才记录来源、目标仓版本、适用条件与结果；负收益时收窄或退出。普通候选不创建目标仓待办。共同组件的已确认缺陷走原事故流程，按一个根因及各处影响分别验证。


本页服务工程复盘；策略/模型学习资产仍沿原research/consumer权威，数据修复归P10。
