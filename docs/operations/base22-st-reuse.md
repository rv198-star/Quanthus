# Retained ST captures and native reuse

`base22_st_reuse.qualify_capture` checks a retained weekly ST observation against
the original dated interval, original notice audit, exact dated listing/venue and
the native status body and lineage. Matching rolling windows are not appended as
new intervals. A proven event requires one matching original notice, including
its effective date. An unproven baseline remains `UNKNOWN` with
`BASELINE_NOT_PROVEN`. This evidence does not recover original provider wire
acquisition or grant historical PIT/consumer admission.

The scoped native reuse job must freeze original manifests and all required local
members before writing. It independently copies native files, retains the whole
original six-member closure and every selected weekly capture/manifest/READY,
checks typed rows, global keys, temporal references and native hashes, and
reproduces the capture proof during cold verification. It must retain the original
metadata gate, including any unknown baseline or excluded universe. A successful
selected-capture proof does not qualify unselected provider states or prove that
August has no other required changes.

No source file, interval endpoint or native knowledge clock is rewritten. The
actual governance verification time is recorded separately. Missing or conflicting
evidence blocks the affected capture. The scope cannot create image `READY`,
mutate CURRENT, activate a consumer or publish a complete Base 2.2.
