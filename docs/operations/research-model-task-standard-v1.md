# Quanthus 研究任务模型分级规范 v1

日期：2026-11-11。依据：#612 对 #609→#610→#611 的独立审计。适用：Quanthus 有限研究、计算执行和资产交付。本文是本轮建议采用的任务分工；数据、分区和生产授权继续使用项目已有合同。

## 决定

保留 Deepseek 4.1 作为受约束执行者；把研究设计、指标语义、结果解释与采用决定交给 Sol 6.1 或具备领域审阅能力的 Astra。作者提交证据，独立审阅者决定阶段验收。任务级别由语义不确定性、错误影响和验证难度决定，代码行数和机器运行时长只用于估算成本。

本轮评价来自一次实际交付；Sol 6.1 尚未做同题受控对照。以下是可立即使用的风险分工，并附后续实测调整条件。

## 日常分级

| 级别 | 任务例子与前提 | 默认执行者 | 开工前必须具备 | 验收与升级 |
|---|---|---|---|---|
| E0 机械执行 | 对固定提交运行已验收脚本、精确HF取数、校验、上传重试、整理回执 | Deepseek 4.1 | 已验收命令与环境锁；精确输入/输出身份；资源及重试上限 | 自动完整性检查；首次任务或异常由独立审阅。未知故障、身份变化立即停相关阶段 |
| E1 有界实现 | 实现已给公式的小指标、补一个明确失败路径、已有接口的局部适配 | Deepseek 4.1 可执行 | Sol/Astra冻结公式、边界样例、版本、golden结果、负例和接受条件 | 独立代码审阅与反例通过后关闭。发现新数据语义或跨两层以上的接口设计时升E2 |
| E2 研究与语义 | 选题/对照、统计口径、上市年龄与warmup、公司行动/收益率、评价分母、资源分配判断 | Sol 6.1 主责；Astra可承接/审阅 | 具名消费者、问题差集、最小样本、事前效应阈值、失败分支、完整预算 | 独立审阅通过后冻结；Deepseek只接拆出的E0/E1工作包 |
| E3 采用与高影响决策 | 候选采用、PIT/受保护分区、资金回放、交易与生产变更、广泛可复用Worker入口 | Sol 6.1 或 Astra 主责，另一个审阅角色验收 | 权限、科学/工程/消费者门槛、回退与最小证据链 | 作者不得独自完成采用；超出现有授权的动作交Owner决定 |

数据源字段存在歧义、指标改变消费者结论、失败路径会错误放行时，即使只需10行SQL，也按E2/E3管理。E0异常升级后保留已完成阶段，避免重复计算。

ROI默认：首次出现、需要现定义公式或验收样例的小任务，优先让Sol完成设计与最小实现，减少交接往返；已有合同和回归资产的重复任务，再交Deepseek执行。只有预期节省超过新增设计交接、审阅和返工成本时才拆分，不为使用低价模型额外造平台或任务。

## 每个任务包的必要字段

1. `proposal_id/task_id/attempt_id`、负责模块、消费者和明确要改变的决定。
2. 固定 Git 完整SHA、HF revision、manifest/config/环境摘要；输入精确成员白名单、用途和已消费分区。
3. 公式、单位、排序/唯一键、缺失处理、时间窗口和warmup；基准、最小有效样本及事前数值决策阈值。描述性任务可不设效果阈值，但其交付仅限描述统计。
4. CPU、RSS、磁盘、下载/上传、墙钟和重试上限；监测方式与真实停止机制。
5. 正常样例与反例：错版本、缺字段、重复键、缺开盘价、超资源、篡改、上传中断、重复交付。
6. 每个阶段的入口/出口、机器可验收证据、失败恢复点；必须通过上一阶段才进入下一阶段。
7. 结果等级、独立验收者、长期最小证据位置、临时TTL和清理责任人。

任务包由领域负责人补齐语义；执行模型遇到缺项应报准确缺口。新增公式或门槛必须建立新版本，不把原结果补写成事前设计。

## 强制升级信号

- 需要自行定义公式、基准、PIT时钟、公司行动处理或消费者门槛。
- 为了绕过依赖而改变问题含义；例如将收益率波动率替换成价格离散度。
- 必需输入缺失但代码能继续、主键重复、结果和回执身份不一致。
- 自审找不到每条验收项的实际日志，或验收内容只有“代码里已有检查”。
- 一次定位后的重试仍失败，或30分钟有界排障仍没有明确新增证据；转上一级处理，完整保留尝试。
- 需要放宽执行/安全/数据门槛，或把描述统计推广为策略、收益或资源配置结论。

- #609：Sol/Astra修订问题合同；明确采用“自定义描述性代理”还是“既有基线语义”。需要总回报时评估现成公司行动接口；共享数据缺口交P10。保存旧请求。

- #611：在新合同通过后，Deepseek执行固定脚本和收集证据；Sol/Astra判断解释与下一笔投入。
- #612：Astra负责本次审阅与处置；保留复算、反例和模型评价证据。
- #613/#614：保留条件触发，不为测试模型或节点而主动扩大研究。

## 用真实交付成本调整分工

后续在自然发生的E0/E1任务中连续记录5个样本：首次验收通过、关键缺陷、审阅主动时间、返工主动时间、机器/网络等待、模型账单和得到的可复用资产。执行时间以平台回执为准，缺失字段写未知。

比较单位是“一个独立验收通过交付”的总成本：设计 + 执行 + 审阅 + 返工 + 算力/传输 + 模型费用。只有账单与工时齐全才计算货币ROI；未测量的成本不按零。

- 关键缺陷指改变结论、身份/分区错误、错误放行或掩盖失败。出现一次就立即收紧该任务类别，先修模板/守卫再恢复。
- 5个自然样本均无关键缺陷且审阅返工成本低于节省成本，保留或有限扩大Deepseek的E1范围。
- 如同类任务可比，Sol也使用相同合同记录实测；不为比较重复消费保护样本。
- 研究方向与最终采用继续独立审阅，模型分级改善后仍保留这一职责分离。
