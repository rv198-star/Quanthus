1. **以完整领域闭合为工作单位。** 先一次分类现存格式和失败原因、固定完整范围，
   集中完成适配；开发中运行适用 focused 回归，领域语义稳定后进行完整物化、
   两次独立冷验收和交接。每次输入或语义变更仍须重验受影响范围。
2. **在昂贵任务前验证前提。** 物理路径、权限、来源闭包、代表性最大分区、查询
   执行计划和实际预算先通过。小样本仅排除工程风险，不替代最终全量验收。
3. **一份当前缺口账本。** #480 的子任务状态和 #486 的逐表账本共同定义当前状态。
   每项列出影响表、键/分区、缺字段/文件、来源身份、已合格输出及下一步。
   验收收据优先于旧的 PENDING；更新只生成新快照，历史证据不可改写。
   输入身份完整且未变的合格中间数据在同一 Job 中共享，不重复物化。
4. **可修数据和缺证据分别处理。** 已核查准确授权 inventory 的缺证据项登记具体
   阻塞；没有新线索不循环重复查找。独立且已批准的工作继续；额外采集、购买、
   凭据、ACL、节点传输等只提交最小具体请求，未授权不执行。
