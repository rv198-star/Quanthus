## 1. 给 Base 2.3.1 构建方的转向指令

**当前正在构建的 2.3.1 直接改以 2.4 为最终版本，不要求先完成、打包或发布一份 2.3.1。** 沿用当前构建工程、合格来源和已完成成果，按本 REQ 补足 2020 起原生 5m、移出默认 1m 依赖，并完成新版本的读取和接续验收；达到要求后以 2.4 发布。未发布的版本声明、配置、文档和输出目标可以据此更新。

先保存当前代码、来源、运行阶段及已通过证据，再识别可复用项。已经封存的 2.3.1 中间镜像、manifest 和验收收据保留原身份，作为前序构建证据；新 2.4 manifest 绑定实际新范围与内容。更改目标版本不需要从头重做，也不能代替新规格验收。正在执行的任务应在可恢复边界收尾，不中断不可恢复写入，不启动与新规格无关的重复重建。

本次成功交付必须同时回答：**2020—2026-09 的 5m 来源实际覆盖到哪里；哪些记录达到什么质量；这些记录是否真实进入 DWD；新代码能否读取这对 Base，并在隔离目录生成 10 月 Daily。** 文件存在、包上传完成或原有验收通过，均不能单独回答这四个问题。

执行方首先回报一份简短接管记录：当前分支与完整 SHA、工作区改动、在途 Job、精确输入身份、2.3.1 已完成/可复用/需重做/缺证据项，以及 2.4 阶段计划和磁盘峰值预算。本文没有把任何尚在构建的 2.3.1 候选认定为最终合格版本。

### REQ-02：分清业务时间和知识时间

必须分别记录业务/观察日期、有效时间、来源发布时间（如有可信证据）、实际取得时间、构建时间、知识 cutoff、各节点实际可见时间。现在取得的历史 5m 可以属于 2020 年业务观察，但其取得时间仍是现在，不能倒填成 2020 年已知。

Base 的业务截止日不等于知识截止日。9 月业务的晚到修订可在声明真实知识时间后纳入 2.4 的冻结输入；10 月业务观察不直接塞入 9 月 Base。跨期状态、报表期末、公告发布日期等由各表原有时间契约决定，不得只按文件名或单一日期字段裁切。构建前将具体选择规则及知识 cutoff 写入输入计划。

### REQ-04：按精确输入复用 2.3.1 成果

可以复用：未改变的原始来源、源码适配、schema、同一语义输入的合格解析产物、已完成证据、共享身份/日历前置。复用身份须覆盖原始字节/manifest、有效视图、代码、模型、规则、证券分母、时间及用途范围；身份变化时只重做受影响部分。

ODS 2.4 是新的不可变来源集合；DWD 2.4 必须以它及明确绑定的不可变补充来源为业务事实输入。**不得从旧 DWD/ADS 或 CURRENT 反向填充事实，不得以 DWD 2.1 或 2.3 数据拼出新 ODS。** 同 Job 的前置候选和缓存仅在现行模型允许、身份闭包完全一致时复用。旧 DWD 的元数据可用于范围盘点，不能替代新来源的验收真值。

旧包 `consumer_admission=NOT_GRANTED`、`execution_authorized=false` 等封存声明不可改写。新版本以新的证据和独立用途收据表达其准入结果，不能继承一个全局“已通过”。

## 4. 原生 5m 来源与覆盖验收

### REQ-06：先证明历史来源可取得，再进行大规模补采

首个执行里程碑应交付“历史来源可行性与成本报告”：明确来源名称/接口/产品版本、可获得年份、适用证券、退市股能力、时间戳语义、价格基准、单位、分页终止条件、访问限制、授权和预算。使用既有合格证据；需要新请求时遵循构建线的采集授权和有限预算，付费来源不擅自购买。

有限样本至少覆盖：2020 年早期、历史范围中段、2026 年 8/9 月、沪深不同板块、跨代码/上市状态案例；退市及新上市案例分别验证。样本可证明接口能力，不能充当全历史完整验收。确认请求上限、磁盘预算与中止条件后，按缺口分片推进。

禁止继续把“向前翻固定页数直到返回空”当作完成 2020 范围。分页到限、空响应、账户封禁、来源无此证券、日期返回错误必须有不同原因码。遇到访问禁止/黑名单，按规定熔断和恢复，使用已合法获准且合格的备用来源，不靠换出口、换身份反复绕过限制。

若现有免费来源无法覆盖早年或退市证券，记录准确日期/证券范围、已尝试的有界证据及可选成本方案。其他独立构建继续，但不把不足的历史缩成新分母后宣布整包达标。

### REQ-07：5m 必须是实有原生观察

默认 5m 产品必须来自经过资格化的原生 5m 来源。不得从日线拆分、插值、补零、残差摊量或残缺 1m 聚合来冒充原生 5m。未来如果确需从完整 1m 聚合，应作为另一个显式派生产品另行审查，不混入本次原生交付。

价格保持来源声明的正确未复权基准，数量/金额单位明确转换，Decimal 精度和时区保持；复权因子及其证据独立，不擅自提供“canonical adjusted price 已合格”的结论。

冻结每个来源的 bar 时间标签、区间开闭、午休、集合竞价、停牌/临停与无成交语义。常规一整天约 48 个 5m 时间桶只能用于规模估计；实际分母按当时交易日历、上市有效期、交易时段和来源约定生成。缺行不能直接解释成停牌或无成交，来源没有返回记录也不能补造 OHLC。

允许跨来源接续，但必须冻结确定性的选择和修订规则，记录每个来源片段与边界；不逐字段暗拼同一根 bar，不以供应商多数票证明真值。来源语义不可比的冲突应隔离到相应观察/消费者，保留可用的其他范围。

采集计划须明确已合格的主来源、备用来源、可重试故障、熔断条件及恢复条件。切换按可审计的完整观察单元进行，保留实际来源标记和缺失字段；备用资格须覆盖该频率和历史范围，日线备用合格不代表其历史 5m 合格。重试与切换共享原预算，恢复后从未完成分片继续，不能无条件重拉所有证券。

### REQ-08：全范围对账，不能只展示 min/max 日期

以 `listing × 业务日期 × interval × price_basis` 为基本覆盖单元，进一步保留桶级缺口。构建方交付机器可读逐日/逐月覆盖账本和按年摘要，至少包含：

- 冻结分母及其来源 digest、适用证券数、适用交易日/会话、预期桶的计算规则；
- 来源实有、ODS 正式准入、DWD 实际入表的证券日数和行数，去重及修订版本数；
- R0/R1/R2/R3 分布、停牌等已证实不适用数、缺证据数和未解释数；
- 观察覆盖率与合格覆盖率，分别给出分子/分母，不能把隔离记录悄悄移出分母；
- 实际最早/最晚日期、连续缺口、来源切换边界，以及“有来源但未入表”的差额；
- 每种异常的原因码、证据身份、用途影响和处理状态。

分母必须包含历史已退市证券及真实历史 listing，不能用今天约 5,200 只证券列表替代多年历史分母。上市前、退市后或权威证据证明不适用的范围单列排除；“找不到数据”不构成排除理由。R0—R3 仅用于现有评级规则覆盖的产品，其他领域按其原有字段/来源准入规则呈现，不套用一个分钟评级覆盖全仓。

## 5. 质量、用途与发布状态

### REQ-09：R2 可受限准入，R3 不得洗成通过

复用并固定现有评级规则及其版本，R2 的含义和既有容差不变。本次改变的是默认所需频率，**不是降低 5m 质量标准**。

| 情况 | 处理与发布边界 |
| --- | --- |
| 所需 5m 单元最低达到 R2，受限事项已披露 | 可以按明确的 gap-aware、非执行用途准入；精度更高的消费者继续执行自己的门槛 |
| 必需证券/日期仍是 R3 或无合格来源 | 原始响应保存在隔离区；相应 5m 产品/联合交付不通过，日频等独立合格产品可继续 |
| R2 中被现有规则允许的局部缺陷 | 明示范围、数量和消费者限制；不能宣称该范围逐桶无缺失或全用途完整 |
| 整年、整月或必需证券系统性未覆盖 | 不得将其包装为笼统 R2；必须展示未覆盖范围，未满足本规格时不能称 Base 2.4 默认历史范围验收成功 |
| 1m 缺失或未评级 | 新默认产品标为 `NOT_INCLUDED`，不进入 5m 的 R3 统计，也不假装已修好旧 1m |
| 非关键财务/股东等局部缺口 | 只阻断依赖该表/字段的消费者，合格行情可独立交付；全领域报告保留真实状态 |

联合交付的 `R3=0` 必须同时证明：正式成员没有 R3，且冻结必需分母中没有被转移到隔离区后仍未解决的 R3/无来源单元。不能仅靠排除坏数据让数字变成零。当前规则未定义的类别先明示为未判定，不自行授予 R2。

必须同时报告“目标范围是否完成”和“已准入数据的质量”；这两个结论不能互相代替。若阶段交付只有合格子集，可标记部分就绪并提供准确范围，不能使用整包“2020 起完整”结论。

### REQ-10：分开记录镜像、产品及消费者验收

每份发布收据分别包含：物理完整性、业务范围覆盖、ODS 来源准入、DWD 实体入表、用途准入、消费者实际读取、Daily 接续、各端交付状态。禁止只给一个 READY。

建议新 profile 标识为 `p10-base24-1d5m-v1`，对应 Base 2.4 与完整 Daily 的 `required_intervals=["1d","5m"]`。这是待实现的新合同标识，**当前生产仍有要求 1d/1m/5m 的旧合同**，不能把本文当成已经生效的配置。

默认用途保持有缺口意识的非执行数据开发/仓库读取；镜像和接续验收不自动授予交易执行、历史严格 PIT 研究、训练、回测或 P3/P5/P6 激活。显式请求 1m 的旧消费者在新产品上应得到缺少所需频率的清楚结果，不能返回 5m 伪装兼容。

## 6. ODS/DWD 物理设计与构建约束

### REQ-11：可独立恢复的 ODS 来源闭包

ODS 2.4 必须包含实际来源数据、规范文件清单、哈希、原生 schema/行 census、必要数据库完整性证据、来源/请求/解析版本以及原始响应关联。新增采集在取得响应时保全原始字节及请求元数据，失败与拒绝响应也留原因收据；凭据必须脱敏或不进入包。

规范 Parquet 不能冒充完整原始 HTTP 响应。旧历史如果只有来源保真的归档文件，记录实际证据层级和用途限制，不伪造当年的请求日志。受影响用途缺乏必要原始证据时单独阻断；其他满足契约的旧来源可按明确授权继续使用。

已验证未变的字节只保存一份或内容寻址去重。独占 1m 数据不进入默认包的必需依赖；包含多频数据的原始证据不得为节省空间直接改写。必须保留共享原始成员时声明其混合内容，或产出可验证的来源投影并保留可恢复血缘，不据此要求分发整份独立 1m 产品。

镜像恢复后必须能在干净目标目录读取，不能依赖构建机上的绝对路径、软链接到旧版本或未列明缓存。外部证据对象如必须引用，须给出不可变身份、恢复方式及实际恢复收据；否则不能声称离线自足。

### REQ-12：新 DWD 的真实读取与身份绑定

DWD manifest 精确绑定 ODS 2.4 manifest/content digest、补充来源、完整代码 SHA、模型/政策/分母/日历身份与知识 cutoff。声明原生版本和布局；不得改 `kind` 冒充旧 Base 来绕过读取器。

保留 Decimal、时间精度、业务键与版本键、外键、listing/venue/calendar 关系、unavailable/null/zero/late 的区别。业务事实、版本及来源必须可追溯；不得将未成功刷新状态改成成功、把缺值改零或覆盖修订前知识。

对当前生产读取器做最小显式适配，保留旧版本读取检查。必须通过真实代码入口在隔离环境读取新 ODS/DWD；测试探针、说明文档或只读一个 manifest 不足以验收。

### REQ-13：可恢复、有限成本的构建

构建采用阶段 DAG，身份、日历等确定性共同前置在同一 Job 内只构建一次。分片有 checkpoint、幂等提交、输入 digest、累计请求/重试预算与耗时；重启不重置预算，不重复全市场拉取已取得的同一响应。

生命周期显式区分临时产物、内容寻址缓存和正式产品；保留策略与依赖闭包明确。旧 2.3.1 成果在证明无后继依赖且具备恢复条件前保留，删除与生产切换由 Owner 另行确认。

工作区优先沿用当前已经隔离的 `codex/` 任务分支和 worktree；无需仅为版本号变化再复制工程。若当前工作区不具备隔离条件，再建立独立分支/worktree，保留他人改动；按接收仓库适用 AGENTS、P10 与当前构建契约执行。代码通过版本库的正常发布路径交付，不能用临时源码包替换生产代码。

## 7. 10 月 Daily 与后续日常流程

### REQ-14：用 Base 2.4 真正生成接续产物

冻结验收时已存在的 10 月 ODS、Daily、自然日公告、周频财务及修订源。先选一个具备完整来源的代表性交易日验证工程路径，再覆盖截至验收时实际待接续范围；不为每个小改动重跑不受影响的昂贵前置。

已经绑定 Base 2.1/2.3 的 Daily 不可只改版本标签。优先复用原始 ODS 和已证明合格的观察，对依赖 Base 的领域前置与产物按新合同重建；只有语义闭包完全相同的不可变分片才可复用，并提供其仍成立的证据。新产物写到隔离目录，精确绑定 Base 2.4；旧产物和原首次交付回执保持不可变。

必须核对 9/30 封存边界与 10 月首个交易日之间的连接，证明没有重复并入 9 月已封存观察，也没有丢失国庆期间或周末的真实公告/财务事件。比较同一冻结 ODS 输入的键、版本、行 census、日历、外键和血缘；允许差异只能来自明确列明的新 Base 修复、频率范围变化、分母修正或真实修订，不能凭总行数相近认定一致。

周频财务和其他变频领域按实际周期和版本接续，不要求每天重复一份完整历史。真实成功子域独立入表，失败子域保留缺口及通知，不能因为部分失败丢弃已有合格财务。

### REQ-15：CN02 承担 T 日盘后主流程，T+1 仅作补采和修订

2026-10-16 查询的 BaoStock 官方平台介绍标注：日 K 线在交易日 17:30 入库，分钟 K 线在交易日 20:00 入库，其他财务报告在下一自然日 01:30 入库。这支持尝试当晚完成行情主产品，但不是本系统实跑验收，也不保证账户可访问、全市场全部来源当日无延迟。来源依据见附录 B。

Base 历史补采、Daily 日频/5m、财务等共享来源访问时，按供应商实际限额统一协调并发、会话与请求预算，避免多个 Job 各自“合规”却合计触发限制。原生 5m 移除 1m 依赖不代表原生 5m 来源的封禁/不可用问题自动消失。

## 8. 容量和运行预算

### REQ-16：先按实际空间预算，不盲目下载或解包

本轮估算基于现有紧凑 Parquet、当前沪深范围和保留其他领域：**两份正式 Base 约 40–50 GiB**，ODS 约 21–27 GiB、DWD 约 18–23 GiB；这不是验收上限，也不是全机磁盘需求承诺。当前 2.3 两份实际恢复镜像合计约 33.25 GiB。

执行前分别列明：现有保留数据、需要新增的来源原始响应、目标 ODS/DWD、压缩包、各阶段 scratch、缓存、回退和余量。按同一时刻最大占用计算，不把共享文件重复计入，也不把所有 scratch 当长期数据。使用当前字节/行估算后，以有限样本实测修正。

CN02 的现有闲鱼服务与当前构建任务必须纳入资源冲突检查；系统盘和数据盘分开预算，配额按实际写入身份验证，不能用磁盘显示空余替代可写额度。沿用必要资源门槛，不静默下调；空间不足时先给出具体缺口与可复用/可回收候选，再推进大批量操作。

没有保证可用的 RT6800 资源。CPU、内存与并发按真实解析/构建样本选择；需要云算力时优先增量输入和可验证缓存，评估上传带宽与成本。不因本 REQ 直接购买节点或执行项目迁移。
