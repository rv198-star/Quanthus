## Concrete acceptance for batch 1

- A named consumer, exact supported contract, and a minimal example that explains which inputs
  are usable and why outputs may be unavailable/abstain. Prefer existing APIs/views.
- A real interface usability gap is identified before code is added. Where existing assets
  already meet the need, no new code is required; repeat model-read smoke is not new progress.
- A required adapter preserves hashes, time semantics and expert/veto precedence. Validate
  with applicable synthetic cases first. Any actual retained-data reading must bind existing
  admitted identities and purpose; this planning file alone authorizes no market-row access.
- Delivery records actual consumer usability and cost, separate from predictive quality,
  economic value and production admission. No archived March fit-driver reuse or hidden repair.
- Scope and tests are appropriate to the change; existing local CI rules apply. Update only
  affected blueprint facets and retain a conclusion showing the resulting next decision.
