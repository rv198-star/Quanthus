## 3. 构建时必须落实的合并规则

### 3.1 ODS 来源与独立恢复

来源成员区分 `provider_raw`、`inherited_ods`、`inherited_dwd_archive`，分别保留原始 SHA、采集或继承时钟、上游固定版本及恢复地址。旧历史部分来自 Base 2.3 DWD 归档，应按该实际类型登记；已有原始响应按原字节收录。

源归档可能同时含日线、状态或其他字段。选择器可以引用不可拆分的完整原件，共享存储只保留一份内容身份；每个产品的恢复清单必须列齐依赖。发布完整档案备份支持独立恢复，日线消费者的 DWD 读取路径保持简单。

### 3.2 参考表与时间坐标

证券、公司、上市关系、日历、生命周期、ST/停牌、限价、因子及公司行动构成共同参考闭包。按业务键、知识版本和有效区间合并，逐值相同的重叠记录去重，差异进入明确处置台账；不同来源及历史质量等级保留。

2020 年已定位 000919、600805、600810 共 729 条自然日坐标。构建阶段扫描全部现代年份，按现有 calendar_session_id 规范为目标日线契约的开收盘坐标，记录全部转换行并验证 OHLCV、成交额及来源值不变。729 是本轮 2020 年计数。

Hist 继承的旧 `tradability_state` 和缺行情原因属于原快照。目标产品按实际选入的行情、日历与状态重新绑定或生成派生状态，旧原因保留为版本对账证据。

原生因子和二元 ST 在完整目标区间重新做覆盖、冲突及接缝检查。2005 年以前保持参考级；000005 最早 18 条行情的因子适用性、跨重组上市切换、ST 细分 #606 均按已登记规则保留。

### 3.3 既有质量处置与其他领域

- 002336、002500 在 2020-06-17 的成交量采用已封存现代 Base 处置，保留 Hist 重叠对账台账。
- 5m 已登记的 000555/2023-12-21、002866/2022-02-21、688065/2023-06-15 及拍卖时段、手数精度等限制逐项继承。按实际物化集合核对旧台账适用范围，单列新增差集。
- 日线与 5m 的跨频率对账遵循已批准的价格、交易时段和数量单位；分钟缺失与合法手数精度差异分别记录。
- 对 Base 的全部 33 张表生成归属清单：频率行情拆分、共同参考、分产品派生状态、其他领域保留。财务、公告、估值、指数、行业、股权等领域继续保留明确存储与版本归属，原始对象和历史封存身份完整保留。

依赖：A → B → C → D → E。工程准备预计 **6–10 小时**，可在月末之前完成。行情包机时为首次拆包的低置信度估算，冻结输入后按实际源字节、成员数及样本阶段吞吐修订。#600 原全域构建的 8.5–9 小时是历史参照，不能直接作为 627 MB 日线的传输或封装时间。

2.6 正式构建在 **11 月 30 日收盘对应 Daily 完成后**启动，目标为 **12 月 1 日完成主节点首轮发布与云端恢复**；若尾部交付出现具体失败，只调整受影响产品并报告实际截止日。此前的日常最新入口仍由 2.5.1 加连续 Daily 提供。

独立节点 C26 的同输入复建列为 E 阶段单独验收，A 阶段核实资源并给出排期；C251 的既有延期继续由 #601 跟踪。工程准备、构建机时、云传输和等待月末使用不同时间口径。容量预算使用选中源成员、四包发布保留量及审计 TMP 实测计算，并检查每盘可用字节和 inode。

## 5. 关键验收清单

1. **来源完整性**：四包全部声明成员逐文件 SHA/size 一致；DWD 每项来源均能按恢复清单定位；继承材料的来源类型、实际知识时钟明确。
2. **时间覆盖**：11 月 30 个日历日各有一个权威选定交付；交易日有相应行情，休市日有日历及事件依据。分别公布两个产品的实际终点。
3. **日线**：按上市有效区间与开市日历构造分母，逐日、月、年、板块输出 observed/zero-volume/suspended/missing；重复键、越界、身份/单位/价格基准错误为 0，未解释缺口为 0。
4. **5m**：按证券、交易日和有效时段逐桶核对，登记完整/停牌/源缺口/已接受限制；常规交易日的桶规则沿用版本化原生频率契约。新增未处置缺口为 0，既有精确限制集可核对。
5. **参考闭包**：所有 FK 可解析；知识版本不重叠；因子链、二元 ST、上市切换与跨段参考均有合格输入；派生状态与目标行情一致。
6. **频率隔离**：日线 DWD 的行情仅为 1d，5m DWD 的行情仅为 5m；删除另一频率下载缓存后，各自的读取与恢复成功。
7. **兼容与演进**：固定组合按最小共同截止日验证多频读取；连续两代 prepare/build/seal 可执行；旧来源工作目录和 TMP 移除后仍能从正式输入重建。
8. **交付**：四包 manifests、来源恢复清单、覆盖矩阵、质量限制、读取示例、验收及云回读回执齐全；每个阶段报告剩余工作与修订后的时间估算。

## 6. 对 #600 原计划的增量

保留 #600 的两入口标准化、30 日历日交付、同版本物化/审计、来源重放、云恢复和独立复建要求。Phase 3 的输出拓扑改为 **日线 / 5m × ODS / DWD**，新增 Hist 历史段、参考闭包、独立读取及四包版本组合验收。
