# R1 批次价值简报

面向：项目负责人；截至：2026-11-12（Asia/Shanghai）。
父项：META-RESEARCH-ROI-001 / [#608](https://github.com/rv198-star/Quanthus/issues/608)。
交付约定：[探索推进准则](../design/exploration-governance.md#user-facing-batch-value-handoff)。
本页解释既有结论及其项目价值，证据来自已完成的独立验收。

**本批主要完成了“把封存数据用于一次可核验研究”的交付验证，并确定近期研究优先级。
工程能力的增量明确，策略认知的增量较窄。下一批应使用这条链路回答一个具名信号问题。**

## 本来要解决什么

项目已有 DWD Base 2.5.1、历史回放和若干基线能力。R1 的任务是把一个具体问题接到 HF
固定数据、限额计算和结果回传上，完成一次可审阅的交付，再决定优先研究信号、执行约束
还是投入更多 Worker。

这批选择的具体问题是：在一套固定的流动性和未复权价格筛选条件下，候选被次日开盘
价格与可交易状态检查拦下的比例，是否达到事前规定的优先调查门槛？

## 实际得到什么，以及改变什么

| 实际产出 | 对项目的推进价值 | 现在的使用方式 |
| --- | --- | --- |
| 2020–2021 年固定筛选中，90,648 个候选机会有 75 个被检查拦下，约 0.083%；年度结果也低于事前调查门槛 | 缩小近期资源选择的不确定性：保留现有 P2 守卫，下一笔优先具名信号问题 | 已记入 small 资源分支，作为下一次选题的依据 |
| 一套经独立验收的单节点 HF 取数、限额计算、固定结果包和回读流程 | 后续合适任务有可复用的执行起点；身份、失败和中断处理已有回归资产 | 维护者为新任务冻结请求、输入和环境后复用；适配工作量由下一次真实调用检验 |
| 一次运行的计算约 61 秒，峰值内存约 3.39 GB、scratch 约 0.83 GB | 后续节点选择和预算有实测参考 | 按具体任务重新核对配额，再决定是否需要第二节点 |
| Deepseek / Sol 的 E0–E3 任务分工及升级条件 | 后续任务下达能把明确执行与研究语义分开，减少隐含判断造成的返工 | 采用现有模型分级规范，在自然任务中积累完整交付成本样本 |

项目在这条新研究交付线上从“有数据和现成工具”推进到“已验收一个具体研究任务的完整交付”。
代码已在 PR #617 的工作分支中，合入 main 是当前仓库收尾项。
策略层面的剩余工作是提出信号候选，并验证其收益、风险和实际采用价值。

## 这笔投入是否值得

本批作为首次 HF 研究交付验证，有明确的工程用途；作为策略探索，其结论只覆盖一套固定
筛选的次日开盘检查，范围较窄。多轮修复与审计使工程和交接投入偏重。

完整主动工时、模型账单和历史总成本仍缺计量，保留为 `unknown_not_zero`。
下一任务是否实际降低准备、审阅和返工成本，仍需一次真实复用来检验。
当前价值判断是：收下已验证的资产和资源决定，结束本题的局部迭代，把下一笔投入转向
更直接影响策略选择的信号问题。

## 下一步与可判断的成功条件

1. 完成 PR #617 的常规代码合并收尾。
2. 下一批先明确一个具名信号问题、现成比较基线、收益/风险评价和完整预算，再执行。
   研究结果应改变至少一个具体候选的采用、拒绝或停放决定。
3. 在该批记录实际复用内容、新增适配、审阅/返工及等待成本，检验本轮执行资产的复用价值。
   第二 Worker 继续按真实任务池或容量缺口触发。
